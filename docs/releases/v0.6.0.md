# ArtSearch v0.6.0

Release date: 2026-09-05

## Public Alpha And Retrieval Assistant

v0.6.0 turns the invite-only search page into a public resume demo and makes
its expensive path observable from the browser. The frontend is now served as
Cloudflare static assets, so opening the workbench does not wake model compute.
Search requests still use one scale-to-zero container with strict concurrency,
upload, content-type, and rate limits.

The deployed request path is:

```text
Cloudflare static workbench and edge controls
  -> scale-to-zero Cloudflare CPU Container
  -> pinned CLIP subject + CSD style query encoder
  -> Qdrant named-vector recall and reciprocal-rank fusion
  -> Neon PostgreSQL catalog and product telemetry
  -> private R2 media through the Worker
```

After ten results render, a lightweight Cloudflare Workers AI assistant can
summarize their bounded Bluesky post and alt-text metadata. It can also invoke
one constrained retrieval tool that reuses the in-memory query image and
searches within a selected displayed artist through an exact Qdrant metadata
filter. The assistant does not inspect query pixels or crawl arbitrary sources.

## Timing And Runtime Visibility

The workbench now reports an end-to-end request trace spanning:

- browser upload and Cloudflare Container wait;
- decode, telemetry initialization, CLIP, and CSD;
- CSD preprocessing, tensor transfer, ViT backbone, projection, and output;
- vector normalization, Qdrant retrieval, catalog lookup, and response work.

The API also emits `Server-Timing`, while a non-starting runtime endpoint powers
a red/green model-state light. The status check does not keep the container
warm and the 15-minute idle timeout remains unchanged.

Telemetry initialization now overlaps model inference. Query completion and
feedback writes remain ordered on one telemetry executor, so feedback cannot
overtake the query record that owns it.

## CSD Performance Investigation

Profiling isolated the CSD ViT-L/14 backbone as the dominant warm-query cost,
with dense matrix multiplication accounting for most sampled CPU time. Local
thread scaling showed that two CPU threads materially improved inference, so
the deployed container moved from 1 vCPU and 4 GiB to 2 vCPU and 6 GiB while
retaining a maximum of one instance.

One live warm validation request measured:

| Stage | Before | v0.6.0 sample |
| --- | ---: | ---: |
| Edge end to end | about 5.2 s | about 2.7 s |
| API total | about 5.0 s | about 2.5 s |
| CSD total | about 3.4 s | about 1.69 s |
| CSD backbone | not separated | about 1.68 s |

These values are individual diagnostic probes, not a statistically valid p95.
The existing telemetry pipeline will establish the post-release distribution
from normal searches.

A reproducible `artsearch-csd-benchmark` command now compares thread settings
and enforces embedding agreement. FP32 ONNX produced too little speedup for its
additional artifact cost. Tested dynamic INT8 variants were much faster but
failed the style-embedding quality gate, so no quantized model was promoted and
the active corpus/index contract did not change.

See [the CSD optimization report](../csd_inference_optimization.md) for commands,
stage measurements, experiment results, and acceptance thresholds.

## Public Edge Controls

- The shared alpha passcode and signed alpha-session flow were removed.
- Static files and liveness checks do not start the paid model container.
- Search, assistant, and feedback routes have explicit rate limits.
- Upload bytes, decoded pixels, formats, result count, inference ownership, and
  container count remain bounded.
- Query images remain in memory only and are not retained.
- R2 corpus objects remain private and are served through the Worker.

The public URL is:

`https://artsearch-alpha-search.aesthetic-search-alpha.workers.dev/search`

## Verification

- Full Python suite: 245 passed, 2 optional tests skipped.
- Ruff linting and changed-file formatting checks passed.
- Worker bindings were regenerated and TypeScript validation passed.
- The Cloudflare container deployment dry run and production rollout passed.
- Live health reported one healthy 2-vCPU, 6-GiB container.
- A cold-start request and an immediate warm request each returned ten results
  through CLIP, CSD, Qdrant, Neon catalog lookup, and private R2 delivery.
- Secret scans found only placeholders and explicit test fixtures. No corpus
  images, databases, vectors, model weights, or local environment files are
  included in the release.

## Known Alpha Limits

- CSD ViT-L remains the primary warm-query bottleneck. A distilled or smaller
  query encoder is the next large performance lever but is outside this release.
- One CPU inference owner means concurrent searches may queue or receive a busy
  response.
- Public access means the URL is discoverable; edge rate limits reduce abuse but
  are not user authentication.
- The assistant summarizes source metadata, not the actual image pixels, and is
  intentionally restricted to displayed artists and the current query.
- Artist opt-out, source-deletion propagation, and result reporting still need
  a complete operator workflow before wider distribution.
- Classification and inclusion do not establish attribution, permission,
  safety, or consent, and do not override artist opt-outs.
