# ArtSearch v0.3.1

Released: 2026-08-13

v0.3.1 adds the first production-oriented data-platform layer around the
existing Bluesky collection, SigLIP qualification, SQLite corpus, and retrieval
pipeline. It keeps the private alpha runnable on one machine while introducing
clear migration boundaries for durable object storage and corpus-scale jobs.

## Highlights

- Added an Airflow 3 intake DAG for collection, classification, corpus routing,
  immutable publication, Polars ETL, retries, and bounded failure policy.
- Added a separate Spark 4.2 corpus audit job for source-version reconciliation,
  decision and artist summaries, exact-hash duplicate reporting, and data-quality
  checks over cumulative Parquet manifests.
- Added lazy Polars JSONL-to-Parquet corpus manifests and daily intake metrics.
- Added local and S3-compatible immutable object stores through `s3fs`, with
  SHA-256 content keys, collision detection, remote verification, and repair.
- Added SQLite `artwork_objects` checkpoints for accepted-original object keys,
  URIs, hashes, sizes, ETags, and publication timestamps.
- Added run-scoped accepted-only publication, including reuse of canonical
  objects when a candidate is an exact duplicate.
- Added explicit HTTPX connection and keep-alive limits to Bluesky API and image
  acquisition clients.
- Added a Python 3.12, Airflow 3.3, Java 17, and PySpark 4.2 Docker Compose
  development runtime, isolated from the Python 3.14 ML environment.
- Added production capacity, implementation research, operating instructions,
  and PlantUML architecture documentation.

## Privacy And Retention

- The complete `data/` tree remains ignored, including images, SQLite databases,
  decisions, candidates, Parquet files, dashboards, caches, and model downloads.
- Local artist rosters, local S3 configuration, Airflow state, and private model
  artifacts remain ignored.
- `.dockerignore` prevents private corpus data and local configuration from being
  copied into container images; local runtime paths are mounted instead.
- Rejected image bytes are not published to durable object storage. Current
  publication selects only `accept` decisions from the run evidence.
- No credentials are stored in TOML or source files. S3 credentials use the
  standard AWS environment, profile, or role chain.

## Runtime Note

The Python, SQLite, object-store, Polars, and real-evidence paths were exercised
locally. The release host did not have Docker or Java installed, so the Airflow
and Spark Python assets were syntax and configuration tested but their container
runtime was not launched during this release. The checked-in container supplies
their required Python 3.12 and Java 17 environment.
