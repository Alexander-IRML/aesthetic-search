# ArtSearch v0.3.2

Released: 2026-08-13

v0.3.2 adds the first scalable retrieval-serving layer to ArtSearch. SQLite
remains the canonical metadata and embedding database; Qdrant is a derived,
versioned index that can be deleted and rebuilt from approved canonical rows.

## Retrieval Architecture

Each approved artwork is represented by two named cosine vectors:

- `clip_subject`: CLIP's semantic and subject representation.
- `dino_global`: DINOv2's global visual representation.

Image retrieval runs both HNSW searches independently and combines their ranks
with reciprocal-rank fusion. The fused shortlist is then reranked with exact
DINO patch MaxSim loaded from SQLite. CLIP and DINO are not concatenated, and
the larger patch matrices are not copied into Qdrant. The final stage limits
repeated results from one artist while retaining every component score and rank
for later evaluation.

Text retrieval uses the CLIP named vector only because DINO has no text encoder.

## Index Lifecycle

- Physical collections are tied to exact CLIP/DINO names, revisions,
  dimensions, vector names, and datatype through a model-bundle hash.
- A stable alias is promoted only after synchronization and exact point-count
  verification succeed.
- A changed model bundle requires a new physical collection instead of silently
  reusing a dimension-compatible index.
- Deterministic UUIDv5 point IDs and SQLite content hashes make publication
  idempotent.
- Reconciliation repairs missing points and count drift, prunes newly
  ineligible rows, and removes untracked remote points.
- Qdrant payloads contain compact filtering and lineage fields, not source
  text, URLs, local paths, image bytes, notes, or credentials.

## Safety Boundary

Qdrant indexes only validated, nonduplicate, current-model rows that are both
explicitly `is_sfw = true` and `demo_eligible = true`. Bluesky rows additionally
require the latest linked artwork-filter decision to be an accepted main-corpus
decision.

This is deliberately independent from SigLIP. Artwork qualification is not an
NSFW classifier and is not permission to expose an image in an alpha demo.
Existing databases migrate `demo_eligible` to false.

The current local corpus check reported:

- 117 validated artworks.
- 117 current CLIP 512-dimensional and DINO 768-dimensional embeddings.
- 117 safety-unknown artworks.
- 0 demo-approved artworks.
- 0 Qdrant-eligible artworks.

No bulk assume-safe operation was added. Policy changes name the exact artwork
IDs being reviewed.

## Operations

The new `artsearch-qdrant` command provides:

- non-secret config and corpus-eligibility reports;
- explicit safety/demo policy updates;
- collection initialization and compatibility checks;
- idempotent synchronization and alias promotion;
- collection status and point counts;
- image-to-image CLIP/DINO fusion with optional patch reranking;
- CLIP text search; and
- per-vector HNSW recall and latency comparison against exact Qdrant search.

The Airflow intake DAG now generates current CLIP/DINO/patch embeddings after
accepted-original publication, reconciles Qdrant, records both summaries in the
run bundle, and only then publishes downstream data products. The development
Compose stack includes a pinned Qdrant service with rebuildable state under the
ignored `data/qdrant/` directory. A separate example configuration supports
Qdrant Cloud through environment-provided endpoint and API-key values.

## Privacy

- The full `data/` tree remains ignored, including source images, processed
  images, SQLite, caches, vectors, Qdrant storage, dashboards, and Parquet data.
- Local Cloud configuration matches `configs/*.local.toml` and remains ignored.
- No tracked image, database, vector, model-weight, or Parquet artifact was
  present in the release payload.
- Qdrant API keys are read from the environment and never printed by the config
  command.

## Runtime Boundary

The host workspace does not provide Docker, so the pinned Qdrant server and
Airflow container were not launched during this release. The Qdrant client and
complete serving behavior were exercised against Qdrant's in-process engine.
Real server HNSW latency and recall at corpus scale remain measurements to run
after reviewed rows are approved and the container or Cloud cluster is online.
